# المرحلة الثالثة — الأمان وCI وسياسة التوقيع (الدفعة B)

## B1 — سياسة CI المُلاحِظة آلياً

أُنشئ `scripts/ci_policy_check.py` وهو يعمل **أول خطوة** في مهمة التحقق (verify) — أي مخالفة مستقبلية للسياسة تُسقط CI قبل أي شيء آخر:

| القاعدة | المضمون | الحالة |
|---|---|---|
| P1 | صلاحيات المستوى الأعلى `{}` (منع شامل) وكل مهمة تعلن صلاحياتها | ✓ |
| P2 | verify = `contents: read` فقط وبلا أي `secrets.` | ✓ |
| P3 | release = `contents: write` + `needs: verify` وبلا صلاحيات إضافية | ✓ |
| P4 | كل `uses:` مثبّت بـ SHA 40-خانة (بلا وسوم عائمة) | ✓ |
| P5 | يُمنع `pull_request_target` نهائياً | ✓ |
| P6 | إنشاء GitHub Release مشروط بوسم **غير موجود مسبقاً** | ✓ |
| P7 | بوابة توقيع الإنتاج موجودة وتُفشل المهمة بغياب المفتاح | ✓ |
| P8 | يُمنع `overwrite_files` (لا تُعدَّل إصدارات منشورة أبداً) | ✓ |

### الإجراءات الخارجية المثبّتة (نفس الإصدارات الكبرى السابقة، صفر تغيير سلوكي من التثبيت نفسه)

| الإجراء | SHA المثبّت |
|---|---|
| actions/checkout | `11d5960a…` (v4.4.0) |
| actions/setup-java | `cf277c60…` (v4.9.1) |
| subosito/flutter-action | `1a449444…` (v2.23.0) |

### إصلاحات نشر حقيقية
- كان كل push على main يعيد إنشاء/تعديل GitHub Release لنفس الإصدار (`overwrite_files: true`) — **أُزيل التعديل** وأُضيف فحص وجود الوسم: الوسم الموجود ⇒ لا إنشاء إصدار (البناء ينتج artifact فقط).
- متن الإصدار يذكر حالة التوقيع الحقيقية دائماً؛ البناء الموقّع بشهادة debug يُسمّى صراحةً **نسخة اختبار** في العنوان والمتن.

## B2 — فحص أمان المشروع

| الفحص | النتيجة |
|---|---|
| أنماط أسرار (ghp_/AKIA/مفاتيح خاصة) في كل الملفات المتتبعة | لا شيء |
| ملفات توقيع (.jks/.keystore/key.properties) في المستودع | لا شيء |
| `print()` في lib/ | لا شيء |
| الأذونات المدمجة النهائية | RECORD_AUDIO + POST_NOTIFICATIONS + VIBRATE + `com.masar.allugha.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (يحقنها androidx، مستوى normal، باسم التطبيق) |
| إذن INTERNET | **غير موجود** (ثابت الخصوصية: عمل كامل دون اتصال) |
| المستقبلات | مستقبلات flutter_local_notifications الاثنان موجودان و`exported=false` |
| **allowBackup** | كان **غير مضبوط** (افتراضي أندرويد = true) ⇒ بيانات المتعلم قد تتسرب إلى نسخ النظام الاحتياطي السحابي. **أُصلح: `android:allowBackup="false"`** — متوافق مع نهج التطبيق دون-سحابة، ولا يغيّر أي وظيفة |
| الاستيراد | تحقق صارم: وسم تطبيق، و IDs تُقارن بالمدونة الحقيقية (تُسقط الأجنبية)، وقيم null-safe للحمولات القديمة |
| السجلات | لا طبع لأي قيم سرية في أي خطوة CI؛ لا تُطبع بيانات التوقيع |

## B3 — سياسة التوقيع (فصل الاختبار عن الإنتاج)

**نسخة الاختبار (الوضع الافتراضي):**
- تُبنى بتوقيع debug عند غياب `android/key.properties` — وهذا **معلن صراحة** في ملخص المهمة وفي متن الإصدار وفي تقاريرنا.
- تصلح للتثبيت التجريبي الجانبي فقط، ولا تصلح للنشر على Play ولا للتحديث فوق تثبيت إنتاجي.

**نسخة الإنتاج (`workflow_dispatch` مع `production: true`):**
- غياب `android/key.properties` ⇒ **المهمة تفشل** برسالة صريحة — لا يُنتج أبداً APK بتوقيع debug ويُقدَّم كإنتاج.
- آلية الإتاحة الآمنة عند توفير الشهادة: أسرار GitHub المشفّرة تُكتب إلى ملفات دون أي طبع (موثقة في تعليقات المسار).
- **لا تملك المشروع شهادة الإنتاج الأصلية** (لا يوجد نشر إنتاجي سابق): لم تُستبدل بشهادة جديدة تلقائياً، ولم يُدَّعِ أي إصدار أنه قابل لتحديث تثبيت منشور. المتطلب الفعلي: مستخدم يوفّر keystore خاصاً عبر الأسرار.
