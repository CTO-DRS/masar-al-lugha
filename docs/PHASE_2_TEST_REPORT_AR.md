## 3) إخفاقات حدثت أثناء التطوير — وكيف حُلّت (للشفافية)

| الفشل | الجذر | الحل |
|---|---|---|
| اختبارا session فشلا بعد بوابة الضعف | البطاقات المركبة في الاختبار كانت سليمة (S=5) — البوابة الصادقة **صحت** في استبعادها | إعادة بناء بطاقات الاختبار ضعيفة فعليًا + اختباران جديدان يثبتان السلوك الجديد |
| `masteryNeedsReview` فشل | `_seen` في الاختبار ترك `dueEpochMs` لقيمته الافتراضية `DateTime.now()` لحظة البناء — انزاحت عن الساعة الثابتة | تمرير `dueInDays` صريح على الخط الزمني الثابت |
| اختبار «ترتيب الاستحقاق» فشل | افتراض خاطئ مني: `easy` يقفز أبعد فترتيب التقييم ≠ ترتيب الاستحقاق (سلوك FSRS **صحيح**) | تصحيح الاختبار ليقيّد الثابت الحقيقي: عزل النكسة + عدم تحريك بطاقات الغير |
| `non_exhaustive_switch` × 3 | إضافة نوع `grammar` إلى التعداد كسرت مفاتيح شاملة في `_make` واختبارين | تغطية الحالة في الثلاثة (mcq-شكل) |
| `audioText فارغ في الوضع الصوتي` (distractors_test) | جولة القواعد الصامتة كسرت عقد «كل جولة مسموعة» | تخطي جولة القواعد في الوضع الصوتي + اختبار يثبته |
| `pattern_type_mismatch` في error_analysis | إتلاف tuple-pattern على `MapEntry` | قراءة `row.key/row.value` مباشرة |
| `undefined AppState / Mastery / Srs` | استيرادات ناقصة بعد الاستخراجات | إضافة الاستيرادات |
| `use_build_context_synchronously` | استخدام context بعد `await init` في `_listen` | حل السياق مرة واحدة أعلى الدالة قبل أي انتظار |
| practicedKeywords فشل (3≠4) | نشر كامل المجموعة الأولى متعددة الكلمات | هدف **أولي واحد** لكل محطة (`first.first`) + اختبار يثبت العلاقة بالبيانات |

## 4) حالة بناء APK

- البناء يُنفذ في CI على دفع `main` بعد مهمة `verify` المستقلة (تحقق المحتوى + التنسيق + التحليل + كل الاختبارات 513) — **جديدة هذه المرحلة**: النشر في مهمة منفصلة بصلاحية `contents: write` وحدها، و`verify` بأذونات قراءة فقط.
- يُحدَّث هذا القسم بعد إغلاق تشغيل CI بالتحقق المستقل (aapt2/apksigner/المحتوى المدمج) في سجل العمل.
